# 專案與「專案等級」說明（OpenCode V2）

> 整理日期：2026-11-19。回家後可直接在本頁閱讀。
> 官方參考：[OpenCode Config](https://opencode.ai/docs/config/) · [CLI Commands](https://opencode.ai/docs/cli/commands/) · [TUI](https://opencode.ai/docs/cli/tui/)

---

## 一、專案是什麼？

**專案 = 一個被當成整體來管理的工作資料夾**，不是單一檔案。

通常包含：

- 程式碼 / 文件
- `.git`（版本控制）
- 設定檔，例如 `opencode.jsonc`、`AGENTS.md`
- 套件設定，例如 `package.json`

以本 repo 為例：

```text
C:\Users\User\Documents\多重代理
├── README.md
├── AGENT_COMMANDS.md
├── .git\
├── .vscode\
├── antigravity\    ← Antigravity 專屬工作區
└── opencode\       ← OpenCode 專屬工作區
```

在 OpenCode 裡，**session（對話）是隸屬於某個專案的**。換到別的資料夾執行 `opencode`，就是開另一個專案的工作階段。

> 在 VS Code 裡常說的 **workspace / 工作區**，和這裡的「專案」幾乎是同一件事。

## 二、專案等級是什麼？

老師常說的「專案等級」，指的是 **設定的生效範圍（scope）**：這份設定只對這個專案有效，還是對你所有專案都有效。

### OpenCode V2 的設定層級（Windows 路徑）

| 層級 | 位置 | 影響範圍 |
| :--- | :--- | :--- |
| 系統 / 管理員 | `%ProgramData%\opencode\` | 整台機器，專案也不能覆蓋 |
| 全域（使用者） | `C:\Users\User\.config\opencode\opencode.jsonc` | 你在**所有專案**都套用 |
| **專案等級** | `C:\Users\User\Documents\多重代理\opencode.jsonc` | 只有**這個專案**套用 |
| 子專案 / 套件 | `...\packages\web\opencode.jsonc` | monorepo 裡更具體的套件，覆蓋上層 |

另有兩種寫法：

- 專案設定可放在 `<專案>\opencode.jsonc`，或 `<專案>\.opencode\opencode.jsonc`
- `cli.json`（快捷鍵、主題、TUI 偏好）**只有全域**，沒有專案等級

### 優先順序口訣

> **越靠近你目前資料夾的越優先；`.opencode\` 裡的又比直接放在資料夾的更優先；系統管理員最大。**

```text
全域  <  專案根目錄  <  子目錄/套件  <  系統管理員
同層：opencode.jsonc  <  .opencode/opencode.jsonc
```

## 三、範例：專案等級設定檔

在專案根目錄放 `opencode.jsonc`：

```jsonc
{
  "$schema": "https://opencode.ai/config.json",
  // 這個專案預設用的模型
  "model": "anthropic/claude-sonnet-5-5",
  // 額外讀取的規則文件
  "instructions": ["AGENTS.md", "docs/規則.md"],
  // 這個專案的權限規則
  "permissions": [
    {
      "action": "shell",
      "resource": "git push *",
      "effect": "ask"
    }
  ]
}
```

意義：

- 換模型、載入規則、限制危險指令
- **只影響這個專案**，不會影響其他作業
- 可以跟著 git 一起繳交 / 共用

> 注意：以上只是範例。目前 repo 尚未真的建立 `opencode.jsonc`，以免改變現有專案行為。需要的話再新增即可。

## 四、為什麼老師一直強調「專案等級」？

1. **可攜**：設定檔進 git，回家 clone 下來就有同樣環境。
2. **不互相污染**：不要為了某份作業改全域設定，影響其他專案。
3. **批改方便**：批改者 `cd` 進資料夾就能得到一致行為。
4. **權限可控**：可以把 `permissions`、`agents`、`mcp` 寫在專案裡，而不是每台電腦手動設。

## 五、常用檢查指令

```powershell
# 列出目前讀到哪些設定來源
opencode debug config

# 改完設定重新載入，不用重開
opencode reload

# TUI 內也可以直接重新載入
/reload
```

## 六、快速記憶

| 問題 | 答案 |
| :--- | :--- |
| 專案是什麼？ | 一個裝著程式碼、`.git` 和設定檔的資料夾 |
| 專案等級是什麼？ | 設定只屬於這個資料夾，不屬於你這個人 |
| 誰最優先？ | 系統管理員 > 靠近目前目錄的 > 全域 |
| 同一層誰贏？ | `.opencode\opencode.jsonc` > `opencode.jsonc` |
| `cli.json` 有專案等級嗎？ | 沒有，只有全域 |
